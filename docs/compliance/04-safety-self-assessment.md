# 04 — 安全自评估报告

> 备案表"安全自评估报告"项对应内容. 这一份是核心, 网信办主要审这一份.

## 1. 评估范围

本报告覆盖 Life OS 服务从输入 → 处理 → 输出的全链路.

## 2. 评估维度 (7 项)

### 2.1 信息安全
- 数据存储: SQLite, 仅服务端, WAL 模式
- 传输: HTTPS only, TLS 1.2+
- 备份: 每日全量备份至独立存储, 加密
- 访问控制: 用户身份基于 UUID, 服务端不存可识别个人信息明文
- 日志: 应用日志保留 30 天, 不含敏感内容

### 2.2 内容安全 (输入)
- 5 类红线检测 (`lib/safety/keywords.ts`):
  1. L3 危机信号 (自伤 / 自杀) → 立刻给热线 + short-circuit
  2. 医疗诊断咨询 → 转介医生
  3. 法律咨询 → 转介律师
  4. 具体投资咨询 → 转介财务顾问
  5. Blocklist (涉黄 / 涉暴 / 涉毒 / 极端) → 拒绝, 不存档
- 命中后**不进入 LLM**, 直接返回硬编码模板

### 2.3 内容安全 (输出)
- LLM 输出经 `sanitizeOutput()` 二次过滤
- 命中 blocklist 时返回中性拒绝, 不暴露原始输出
- 所有长输出 (Decision / Sunday Review / Brain) 自动追加 "AI 生成" 标识

### 2.4 价值观对齐
- 反鸡汤宪法 (`lib/decision/anti-chicken-soup.ts`):
  - 不输出励志 / 抽象哲理
  - 不主动安慰, 仅在用户明确求助时给共情
  - 不假装有答案, 帮用户看清结构
- 边界提示强制 (system prompt 第一段):
  - 涉医疗 → 建议医生
  - 涉法律 → 建议律师
  - 涉投资 → 建议财务顾问
  - 涉自伤 → 提供心理援助资源

### 2.5 用户身份
- V0: 客户端 UUID, 服务端只存哈希
- V1: 邮箱绑定 (验证邮件), 后续可选手机号实名 (按规定)
- 不允许未成年人 (用户协议 + 注册时确认)

### 2.6 数据可控
- 用户随时导出 (`/api/account/data?download=1`)
- 用户随时删除 (`DELETE /api/account/data`, 二次确认)
- 不留备份 (删除即不可恢复)

### 2.7 训练数据隔离
- 不自训, 全部调用第三方
- 调用方关闭训练授权
- 数据不出境 (V1 公开服务)

## 3. 已识别风险 + 缓解措施

| 风险 | 严重度 | 缓解 |
|------|--------|------|
| 用户输入自伤信号 | P0 | `safety/keywords.ts` crisis 检测 + 硬编码热线响应 |
| LLM 输出涉医 / 涉法建议 | P1 | 系统提示边界提示 + 输出 sanitize |
| 用户提到他人 (隐私) | P1 | 用户协议明示"不要写他人可识别信息"; 内容只在自己账户内 |
| LLM 幻觉 (编造记忆) | P1 | "记忆诚实原则" 写入 Pulse / Decision prompt: 没有的事必须问 |
| 模型 API 不可用 | P2 | Model Router 三模型兜底 (DeepSeek 主, Claude/GPT 备) |
| 数据泄露 | P2 | HTTPS + 数据库不暴露公网 + 备份加密 |
| 用户身份冒用 | P2 | UUID 仅用户本地; V1 加邮箱验证 |
