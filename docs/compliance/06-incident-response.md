# 06 — 用户举报 + 应急响应机制

## 1. 投诉 / 举报接收

### 1.1 渠道
- 邮箱: complaint@lifeos.cn (主, 待开通)
- 在线: /feedback 页面 (待开发)
- 电话: (待补 — 法人手机, 工作时间)

### 1.2 接收承诺
- 邮箱: 24 小时内首次响应
- 在线: 提交后立刻返回回执编号
- 电话: 工作时间内 30 分钟回拨

### 1.3 投诉类别 + 优先级
| 类别 | 优先级 | 响应时限 |
|------|--------|----------|
| 涉自伤 / 紧急生命安全 | P0 | 立即 (≤ 1 小时) |
| 涉违法违规内容 | P0 | 6 小时内 |
| AI 输出严重错误 / 造成损失 | P1 | 24 小时内 |
| 数据导出 / 删除请求 | P1 | 7 个工作日内 (PIPL 要求) |
| 功能投诉 / 改进建议 | P2 | 14 个工作日内 |

## 2. 应急响应流程

### 2.1 P0 (生命安全 / 违法违规)
1. 投诉接收人在 IM 群同步主管 + 法务
2. 立刻定位涉及的用户 / 内容 / 调用记录
3. 决策: 是否暂停该用户访问 / 是否撤回相关输出
4. 1 小时内首次回复用户
5. 6 小时内向当地省网信办上报 (依《管理暂行办法》第十六条)
6. 24 小时内出具书面情况说明
7. 7 天内完成根因分析 + 修复 + 复盘报告

### 2.2 P1 (严重错误)
1. 工作时间内 2 小时同步主管
2. 24 小时内首次回复用户
3. 3 个工作日完成核查 + 应对方案
4. 修复后告知用户

### 2.3 P2 (一般投诉)
- 邮件 / 工单跟进, 走标准流程

## 4. 暂停 / 撤回机制

- 单用户暂停: 通过 admin tool 标记 user.status = 'suspended', 该用户所有
  API 返回 503 (维护中提示)
- 单条内容撤回: 删除 decisions / pulses / sunday_reviews 对应行
- 全平台暂停: 系统级 feature flag (DISABLE_AI_GENERATION=1), 所有 LLM 调用
  返回固定文案

## 5. 用户告知

- 重大事件 (服务异常 / 内容下架 / 安全事件) 通过邮件通知受影响用户
- 7 日内在 `/about` 或 `/announcements` 公告说明 (按 PIPL 第五十七条)

## 6. 与监管沟通

- 月度: 总结当月内容审核情况, 内部存档
- 季度: 备案信息复核, 若有重大变更主动报备
- 年度: 安全自评估报告更新, 主动报送

## 7. 记录保存

- 投诉记录: 6 年
- 应急响应记录: 6 年
- AI 调用日志 (含 user_id, prompt 哈希, 输出哈希, 时间): 6 个月
- 违规内容审核日志: 6 年

存储位置: 自有服务器 + 加密备份, 不出境.
